# 界面升级方案 · 2026-11-28

> 目标只有一个：在高复杂度任务下，让用户更快看懂「现在怎么样、下一步做什么」，同时把界面做得更干净、更有秩序。
> 保留既有像素印刷视觉语言（纸张黄 / 墨绿描边 / 硬投影），不引入构建工具与运行时依赖。

## 1. 优化目标

| 目标 | 现状 | 升级后 | 度量方式 |
| --- | --- | --- | --- |
| 3 秒内看懂任务状态 | 首屏是消息流，结论埋在最后 | 首屏第一块是任务概览：状态、质量门、用时、工序、改动、token + 最多 3 条待关注 | 首屏截图人工验收 |
| 主操作不超过 1 次点击 | 顶栏并排 4 个按钮 + 6 个 tab | 顶栏只留 1 个状态相关主按钮（开始 / 重新运行 / 停止），其余收进「⋯」 | DOM 断言 |
| 左栏先看到任务 | 9 个同权重工具链接把任务列表挤到底部 | 任务区常驻顶部，团队与工具折叠 | DOM 断言 + 截图 |
| 详情不抢注意力 | 右侧 372px 常驻、6 个 tab | 默认收起为 62px 竖条（结论 → 详情），需要时展开 | 浏览器用例断言 `insp-collapsed` |
| 长内容可控 | 评审长文、JSON 全量铺开 | 超过 400px 自动折叠，提供「展开全文」 | 截图 |
| 窄屏可用 | ≤980px 时三栏互相挤压 | 单列 + 抽屉，输入区换行 | 1366 / 820 截图 |

## 2. 诊断（当前问题）

1. **三栏同权重**：任务、消息、详情同时争夺注意力，右侧 6 个 tab 与中部阶段条重复表达「进度」。
2. **结论在底部**：进入任务默认滚到底部，先看到的是过程噪声，不是结果。
3. **左栏工具化**：「扫描 CLI / 接入工具池 / 智能分工 / 体检 / Provider / Automation / 审批」7 个入口与任务列表同级。
4. **输入区过载**：工作区、流程模式、优先级、@成员、附件、发送并排一行，认知负担高。
5. **长文无节制**：评审结论、VERDICT JSON、交付清单整块铺开，缺少层级与折叠。
6. **视觉噪音**：双层描边、密集硬投影、10–11px 小字占比过高，扫读困难。

## 3. 信息架构调整

```
左栏（任务优先）            中栏（结论优先）              右栏（按需详情）
├ 品牌 + 新建任务          ├ 任务头：标题 / 状态 / 主操作   ├ 默认收起 62px 竖条
├ 任务搜索 + 状态筛选       ├ 阶段条（5 段，可点）           ├ 展开后 6 个 tab 归并为阅读顺序：
├ 任务列表（常驻）          ├ 任务概览卡（新）               │  结论（上下文/讨论）→ 执行（链路/统计）
├ 团队（折叠）              ├ 消息流（长文折叠）             │  → 产物（工作区/文件）
└ 工具与设置（折叠）         └ 输入区（主输入 + 选项折叠）
```

- 左栏职责收敛为「选任务」，工具类入口全部下沉到「工具与设置」折叠区。
- 中栏承担「看结论 + 做决定」，不再承载配置类操作。
- 右栏从「常驻面板」变成「按需抽屉」，收起时保留明确的展开标签。

## 4. 交互流程简化

| 场景 | 旧路径 | 新路径 |
| --- | --- | --- |
| 看任务结果 | 进入 → 滚到底 → 找收口消息 | 进入 → 概览卡直接给状态、质量门、待关注 |
| 重新运行 | 顶栏「重新编排」按钮 | 顶栏唯一主按钮（已结束时显示「重新运行」） |
| 导出 / 工作区 / 设置 | 顶栏散落按钮 + 右栏 tab | 「⋯」菜单统一入口 |
| 选工作区 | 输入区常驻按钮（与优先级同行） | 保留在输入栏首项，其余选项收进「选项」 |
| 找历史任务 | 滚动长列表 | 搜索框 + 全部/进行中/待处理/已交付筛选 |
| 看执行细节 | 直接面对 6 个 tab | 概览卡「执行详情 →」一键展开右栏 |

## 5. 视觉层次改进

- **字阶**：9.5 / 11 / 12.5 / 15 / 21（像素字仅用于数字与标题），正文行高 1.5–1.6。
- **色彩语义**：主操作用橙（`--orange`），状态点用叶绿（通过）、湖蓝（运行）、黄（等待）、橙（失败），其余保持纸黄与墨绿。
- **边框规则**：卡片只保留一层 2px 描边 + 4px 硬投影；内部不再叠加第二层边框，分组改用虚线或留白。
- **间距**：8pt 栅格，卡片内边距 14–16px，模块间 12–14px。
- **可读宽度**：概览与消息列最大 960px 居中，避免超宽行。

## 6. 复杂任务呈现

1. **任务概览卡**：状态 + 质量门 + 用时 / 工序 / 改动文件 / tokens 四项指标 + 最多 3 条「需要关注」（成本待确认、质量门失败、无测试入口、同模型自审、等待原因）。
2. **长消息折叠**：内容高度超过 400px 自动折叠并加渐隐，提供「展开全文 / 收起」。
3. **默认看开头**：切换任务重置到顶部，只有停留在底部时才跟随流式输出。
4. **待确认直达**：成本超阈值的任务在概览卡直接给「确认开工」，不必再点任务卡片走弹窗。
5. **执行轨迹分层**（P1）：按阶段分组，失败优先，合并「产出 1 个文件」这类重复行。

## 7. 改造范围与优先级

### P0（本次已实施）

| 范围 | 内容 | 预期效果 |
| --- | --- | --- |
| 左栏 | 任务搜索 + 状态筛选、任务区置顶、团队/工具折叠 | 打开即见任务，工具不再抢位 |
| 顶栏 | 主按钮随状态变化、新增「⋯」菜单（工作区/导出/设置/夜巡） | 主操作唯一，次要操作不占位 |
| 中栏 | 任务概览卡、切换任务回到顶部 | 首屏即结论 |
| 消息 | 长文自动折叠 | 过程噪声可控 |
| 右栏 | 默认收起 + 竖向「详情」入口 + 概览卡「执行详情 →」 | 三栏不再同时争夺注意力 |
| 输入区 | 「选项」折叠（流程模式/优先级/@成员），工作区保留可见 | 输入区从 8 个控件降到 3 个 |
| 响应式 | ≤980px 单列 + 抽屉 | 窄屏可用 |
| 视觉 | 字阶、边框、间距、状态色整理 | 扫读更稳，噪音更少 |

### P1（下一轮）

- ⌘K 命令面板：切任务、新建、导出、打开工作区、体检。
- 执行轨迹按阶段分组 + 失败优先 + 去重计数。
- 密度切换（舒适 / 紧凑）。
- 右栏 tab 由 6 个归并为 3 组（结论 / 执行 / 产物）。

### P2（后续）

- 移动端手势（左右滑切任务/详情）、底部抽屉。
- 键盘全导航与焦点环规范。
